# catcam 設計

最終更新: 2026-10-17

## 1. ゴール

| # | 機能 | 内容 |
|---|---|---|
| ① | 動き → 形の似た猫 | 動いた領域（手・腕・髪・持ち物）ごとに、シルエットの形が最も近い猫の切り抜きを選んで偽ウィンドウ内に貼る |
| ② | 顔 → 猫顔 | 人の顔の目・鼻の位置に猫の顔の目・鼻を合わせるよう変形して重ねる |

体験の基準は元動画と同じく「キビキビ追従する」こと。**検出から表示までの遅延を 1〜2 フレーム以内**に収める。

非ゴール: 生成 AI による猫化、手 → 肉球などの部位別差し替え（②の拡張として将来検討）、Syphon 入力、録画機能。

## 2. 全体構成

```
AVCaptureSession (720p BGRA, IOSurface)
        │ CVPixelBuffer
        ├──────────────► CVMetalTextureCache ──► カメラテクスチャ（コピーなし）
        │                                              │
        ├─► [motion queue] vImage 縮小 160×90 gray     │
        │      └─► CatCore.MotionDetector              │
        │            差分 → 閾値 → 膨張 → 連結成分     │
        │            → Blob[] (bbox, 16×16 マスク, 記述子)
        │      └─► CatCore.Tracker  (ID 付与・寿命・残像)
        │      └─► CatCore.CatMatcher (猫を割り当て、ヒステリシス付き)
        │                                              │
        └─► [face queue, 15fps] Vision FaceLandmarks   │
               └─► CatCore.SimilarityTransform（人 3 点 → 猫 3 点）
                                                       ▼
                                   FrameState（その時点の描画指示一式）
                                                       ▼
                         Renderer (MTKView, 1 draw call 群 / フレーム)
                         全画面・透明・クリック素通しのオーバーレイ NSWindow
```

スレッド:
- capture コールバック → motion 処理をその場で同期実行（2ms 未満なので別キュー不要）
- face は別キューで非同期。処理中なら新フレームは捨てる（キューを溜めない）
- 描画は MTKView の display link。最新の FrameState をロックで受け取るだけ

## 3. 動き検出（CatCore.MotionDetector）

入力は 160×90 の 8bit グレースケール。

1. **背景モデル**: 前フレームとの差分ではなく指数移動平均の背景 `bg = bg*(1-α) + cur*α`（α≈0.1）との差分。前フレーム差分だと動きの縁だけが出て中身が抜けるため
2. **閾値**: `|cur - bg| > T`。T は Sensitivity から算出（sens 70% → T≈20 目安）
3. **膨張** 3×3 を 2 回で、指の間などの穴をつなぐ
4. **連結成分ラベリング**（2 パス + union-find）
5. **フィルタ**: 面積 < Minimum size は捨てる。上限 `maxBlobs`（既定 24）を面積の大きい順に
6. 各 Blob について:
   - `bbox`（正規化座標 0..1）
   - `mask16`: bbox 内のマスクを 16×16 に縮小した 256bit（`UInt64` × 4）
   - `aspect` = w / h
   - `fill` = 面積 / bbox 面積
   - `orientation`: 2 次モーメントから主軸角（v1 では記録のみ。マッチングには使わない）

~~顔の領域と重なる Blob は除外する~~ → 2026-10-17 変更: **顔も腕と同じく動いた画素から出す**（顔専用の整列した枠は不自然だったため）。
顔の矩形（15% 広げたもの）の中だけは、直近 1 秒以内に動いた画素も動いているとみなし、瞬きや口の動きでもウィンドウが残るようにする。顔検出の結果は、この保持領域を決めるのと M4 のランドマーク合わせに使う。

**最大サイズでの分割**: 塊の幅・高さが最大値（既定は映像の高さの 25%、ほぼ正方形）を超えたら等分のマス目に分け、マスごとに中の画素へぴったり合う矩形にする。空のマスは捨てる。

**人物マスクによる絞り込み**（2026-10-17 追加。背景の部屋が映る・背景の動きに反応するのを避けるため）:
- `VNGeneratePersonSegmentationRequest`（quality `.balanced`、15Hz 上限、シーケンスハンドラで時間平滑化）で人物マスクを得る
- 160×90 に縮小・二値化したマスクを `gate` として渡し、「差分あり かつ 人物」の画素だけを動きとみなす
- 描画でも同じマスクで中身を切り抜く（§7）

## 4. 形マッチング（CatCore.CatMatcher）

### 猫ライブラリの記述子
各猫切り抜きについて、Blob と同じ定義で `mask16` / `aspect` / `fill` を事前計算する。左右反転版もエントリとして持つ（実質 2 倍）。

### 距離
```
d = w1 * hamming(mask16_a, mask16_b) / 256
  + w2 * |log(aspect_a / aspect_b)|
  + w3 * |fill_a - fill_b|
```
初期値 w1=1.0, w2=0.5, w3=0.3。aspect の対数差で事前に絞り込み（±0.4 以内）、残りを全件比較。
2,000 体 × 反転 2 = 4,000 件でも popcount 4 回 × 4,000 回なので 0.1ms 未満。

### 安定化（ちらつき防止）
- 割り当ては **Track 単位**。Blob 単位で毎フレーム選び直さない
- Track は現在の猫との距離が `d_current > d_best + margin`（margin=0.08）の状態が **6 フレーム連続**した時だけ乗り換える
- 同一フレームで同じ猫が複数の Track に出ないよう、上位 k=5 候補から未使用のものを取る

### 貼り方
- 猫の bbox を Blob の bbox に合わせて拡縮する。縦横比の歪みは 1.25 倍までに抑え、超える分は余白
- アルファは猫自身の切り抜きマスクを使う（Blob マスクで切ると猫が欠けて見えるため）
- ウィンドウ内の背景はカメラ映像の同じ領域。つまり「その場所の映像の上に猫が乗っている」見た目

## 5. 顔 → 猫顔

### 実行時
- `VNDetectFaceLandmarksRequest` を 15fps で回す（毎フレームは不要）。間のフレームは前回の結果を線形補間で予測
- 人の 3 点: 左目中心・右目中心・鼻先
- 猫の 3 点: 同上（ライブラリ作成時に取得済み）
- 最小二乗の**相似変換**（回転・等倍拡縮・平行移動）を解き、猫顔を変形して描画
- 猫顔の縁は楕円のフェザーマスクで馴染ませる
- 顔ウィンドウのタイトルは `cat#<trackID>`

### 猫顔のランドマーク取得（ビルド時）
- `VNDetectAnimalBodyPoseRequest`（macOS 14+）で猫の `leftEye` / `rightEye` / `nose` を自動取得する
- 信頼度 < 0.6 の画像、または両目の間隔が小さすぎる（横顔）画像は除外する
- 選ばれる猫顔は Track ごとに固定。キー操作で次の猫に切り替え

## 6. 性能・メモリ予算（M1 / 8GB）

| 項目 | 予算 | 根拠 |
|---|---|---|
| CPU 使用率 | 合計 15% 未満（1 コア換算） | 動き処理は 160×90 で実質 1〜2ms / フレーム |
| 動き処理 | 2ms / フレーム以下 | 縮小・差分・ラベリングすべて 14,400 画素 |
| 顔処理 | 15fps・非同期 | Vision は Neural Engine で動く |
| 描画 | 1ms 未満（GPU） | 四角形を最大 ~100 枚描くだけ |
| GPU メモリ | 300MB 以下 | 下表 |
| 常駐メモリ | 500MB 以下 | 8GB 機で他アプリと共存させるため |

猫テクスチャ:
- 形マッチング用: 1 体 128px のセル、4096² の RGBA アトラス 1 枚（64MB）で 1,024 体。v1 はこれで足りる。足りなければ 2 枚目
- 猫顔用: 512px × 最大 64 体を別アトラス（64MB）

**実測**（2026-10-17、M1 / 30fps、release ビルド）:

| 構成 | CPU |
|---|---|
| 描画のみ | 3.3% |
| ＋カメラ＋動き検出 | 12〜18% |
| ＋顔検出（Vision 10Hz・GPU 縮小入力） | 15〜25% |
| ＋人物セグメンテーション（balanced 12Hz、1 回 18ms） | 25〜29% |

macOS のビデオエフェクト「リアクション」が有効だと、カメラを使うプロセス内で手・顔の検出が走り、数〜十数 % 上乗せされる。アプリからは切れない（読み取り専用）ので、操作パネルの「Video Effects…」からユーザーに切ってもらう。

**やらないこと**（重くなる原因）:
- 本物の NSWindow をウィンドウ数分作る → 1 枚のオーバーレイに偽ウィンドウを描く
- フル解像度で CPU 処理 → 必ず縮小画像で検出し、描画はカメラテクスチャの参照だけにする
- 毎フレーム CGImage を作る → テクスチャのみで完結させる

## 7. 描画（Renderer）

- オーバーレイ: 枠なし・透明・`ignoresMouseEvents = true`・全スペース表示・レベル `.floating` の NSWindow に MTKView を 1 つ
- 偽ウィンドウ 1 枚 = 次の 4 つを順に描く
  1. 影（9-slice のぼかし済みテクスチャ）
  2. タイトルバー（信号ボタン付き、9-slice。タイトル文字列は CoreText で事前にテクスチャ化してキャッシュ）
  3. 中身の背景: カメラテクスチャの UV 部分。人物マスクがあれば人物以外は暗いすりガラス（不透明度 0.22）にする
  4. 猫: アトラスの UV 部分、アルファ合成
- **ウィンドウは追従しない**（2026-10-18 確定）: 動いた場所に湧き、そこから動かない。重なる動き（IoU ≥ 0.3）が続く間は残り、外れたら新しい場所に湧く。腕を振ると軌跡に沿って点々と湧く。顔も同じで、見えている間は 1 枚、外れたら湧き直す
- **止まったら固定**: 動きの面積合計が小さい（≒止まった）間は、その時点のウィンドウ群をその場に残す。再び動いたら、対応しない固定ウィンドウは即座に消す
- 消滅: 動きが外れたウィンドウは 0.4 秒かけてフェードアウトする
- ~~残像~~・~~目・鼻・口のパーツウィンドウ~~: 試して不採用。パーツの位置は M4 の猫顔合わせ用に検出だけ続ける
- 表示モード: オーバーレイ（デスクトップ上）/ ウィンドウ（通常ウィンドウ内に背景付き）

## 8. 操作パネル

SwiftUI の NSPanel。元動画のパネルに準拠する。

- Source: 内蔵カメラ / 連係カメラ（デバイス一覧）
- Motion: on/off, Sensitivity, Minimum size, Max windows, Trail length
- Face: on/off, 猫顔の切り替え
- Display: Overlay / Windowed, Labels, ミラー反転
- 状態表示: fps, 動き処理 ms, Blob 数
- Esc で終了

## 9. 猫ライブラリ（catlib-builder）

### 入力データ
- **Oxford-IIIT Pet Dataset**（猫 12 品種・約 2,400 枚、ピクセル単位の trimap 付き、CC BY-SA 4.0）
  - 作った映像を公開する場合はクレジットが必要
- 任意: 自前の猫写真。`VNGenerateForegroundInstanceMaskRequest`（macOS 14+）で自動切り抜き

### 取得と生成
```
mkdir -p data/oxford-pets && cd data/oxford-pets
curl -LO https://www.robots.ox.ac.uk/~vgg/data/pets/data/images.tar.gz       # 約 790MB
curl -LO https://www.robots.ox.ac.uk/~vgg/data/pets/data/annotations.tar.gz  # 約 19MB
tar xzf images.tar.gz && tar xzf annotations.tar.gz && cd ../..
swift run -c release catlib-builder   # → catlib/shape_atlas.png, catlib/index.json（約 8 秒）
```
クレジット: O. M. Parkhi, A. Vedaldi, A. Zisserman, C. V. Jawahar, "Cats and Dogs", CVPR 2012（CC BY-SA 4.0）。

### 処理
1. trimap（前景 = 1、境界 = 3 は半透明）から切り抜き、前景の bbox でトリミング
2. 細すぎる・欠けている（前景が画像端に大きく接している）ものは除外
3. 長辺 128px に縮小してアトラスに詰める
4. `mask16` / `aspect` / `fill` を計算
5. 同じ画像で AnimalBodyPose を実行し、条件を満たすものは顔の 3 点を記録し、猫顔アトラス（512px）にも入れる
6. 出力: `catlib/shape_atlas.png`, `catlib/face_atlas.png`, `catlib/index.json`（UV・記述子・ランドマーク）

形の多様性を確保するため、aspect の分布を見て偏りがあれば間引く（丸まった猫ばかりにならないようにする）。

## 10. テスト方針（TDD）

`CatCore` は純粋関数・値型で書き、Red → Green → Refactor で進める。

| 対象 | テスト例 |
|---|---|
| ConnectedComponents | L 字・離れた 2 塊・斜めにつながる画素（8 近傍）を正しく数える |
| Morphology | 膨張で 1px の隙間が埋まる |
| ShapeDescriptor | 正方形の fill=1・aspect=1、横長矩形の mask16 が期待ビット |
| CatMatcher | 縦長 Blob に縦長猫が選ばれる / ヒステリシスで 5 フレームでは乗り換えない |
| Tracker | IoU 最大で ID を引き継ぐ / 見失って一定時間後に消える |
| SimilarityTransform | 既知の回転・拡縮・平行移動を 3 点から復元できる |

アプリ層（カメラ・Metal・Vision）は手動確認と、fps / 処理時間の画面表示で検証する。
